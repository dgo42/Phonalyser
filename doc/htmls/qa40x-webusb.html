QA40x from the browser — WebUSB proof of concept

Reads the QuantAsylum QA402 / QA403 live status registers — USB bus voltage, USB bus current and die temperature — straight from a browser tab, with no native code and no plugin. It is a feasibility probe for a browser-side QA40x backend, not a port: it only reads three registers and never starts streaming.

WebAssembly is not what makes this possible — WebUSB is. WASM is just compiled code running in the same sandbox; it gains no I/O capability the page does not already have. Compiling libusb to WASM still needs a transport underneath, and in a browser that transport is navigator.usb. For three register reads the WebUSB calls are a handful of lines, so this page talks to the device directly and skips WASM entirely.

Requirements

  • Chrome or Edge (desktop). Firefox and Safari do not implement WebUSB.
  • A secure context: serve over https:// or http://localhost. Opening this file as file:// will not work — python -m http.server 8799 -d doc/htmls then http://localhost:8799/qa40x-webusb.html.
  • The analyzer must be bound to a WinUSB-class driver on Windows (the same one the desktop app's libusb backend uses). If the QA40x already works in Phonalyser, this is already the case.
  • Close Phonalyser (and the vendor app) first — the interface is claimed exclusively; only one process can hold it.

What this proves (and what it does not)

  • Proves: a browser tab can enumerate, open, claim and run the QA40x register protocol — the same 5-byte big-endian frames the desktop backend sends.
  • Does not prove streaming. Audio needs sustained bulk transfers on EP 2 / 82 with several transfers in flight; WebUSB's transferIn/Out are promise-based per transfer, so a real backend would need a queue depth experiment before any conclusion about dropout-free 192 kHz duplex.
  • Driver binding is the practical blocker, not the API: on Windows the device must be on WinUSB, which is a per-machine setup step a web app cannot perform.
